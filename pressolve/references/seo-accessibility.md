# SEO and Accessibility

## Technical SEO

Inspect actual rendered and HTTP behavior rather than plugin settings alone:

- Status codes, redirects, canonical URLs, and duplicate routes
- Indexability, robots directives, XML sitemaps, and crawl paths
- Titles, descriptions, headings, internal links, and image alternatives
- Structured data validity and consistency with visible content
- Pagination, filters, faceted navigation, multilingual/hreflang behavior
- Mobile rendering, performance, JavaScript dependencies, and soft 404s
- Migration redirects and Search Console/Bing verification where available

Do not guarantee rankings or traffic. Separate crawl/indexing problems from content quality and competitive factors. Verify plugin-specific steps with current official documentation.

## Accessibility review

Use WCAG principles and test meaningful user journeys. Check:

- Semantic landmarks and heading hierarchy
- Keyboard access, logical focus order, and visible focus
- Menu, dialog, accordion, carousel, and form behavior
- Labels, instructions, error identification, and status announcements
- Text and non-text contrast
- Alternative text and decorative-image handling
- Zoom/reflow, orientation, responsive layout, and target size
- Captions/transcripts and motion controls

Automated scans find only part of accessibility problems. Clearly distinguish automated results, code inspection, and manual keyboard/screen-reader testing.

Do not fix accessibility by hiding focus, disabling zoom, adding unnecessary ARIA, or using overlay claims as proof of conformance.
